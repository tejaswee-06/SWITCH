# SWITCH shared contracts

One contract is used by the backend (Person 2), the interpretation/repair modules (Person 3C), the Alexa+ adapter and
the frontend (Person 1). Where an earlier module used different names, an explicit translation function exists and is
tested; nothing is silently dropped.

## 1. Rooms and devices — `contracts/canonical_home.json`

* 8 rooms: `living, kitchen, bedroom, bathroom, hallway, bedroom2, bedroom3, patio` (numbers 1–8 = the 3D villa's room
  markers; verified against the GLB by `tests/geometry.test.mjs`).
* 35 devices: 8 lights `<room>_light` (power on/off), 4 fans (`speed`), 4 AC units (`power`, `mode`), `tv`,
  `air_purifier`, `coffee_machine` (power), `security` (`armed` true/false), 6 glass doors (`open`), `front_door`
  (`locked`; backend-only, no 3D fixture), 8 read-only occupancy sensors `<room>_occupancy` (`occupied`).
* `fe_id` = the browser simulator / GLB id (e.g. `hallway_light` → `hallwayLight`); `null` = modeled by the backend only.
* Consumers: `switch_backend/app/catalog.py` (CATALOG), `switch_backend/app/p3c_bridge.py` (Person 3C catalogs),
  `src/contracts/canonicalHome.js` (generated by `npm run contract:sync`), `src/api/canonicalMap.js`.
* Tests: `test_contract_matches_frontend_simulator_ids_and_rooms` (pytest) and `tests/canonical.test.mjs` fail on drift.
  The six original Person 2 devices keep identical ids/attributes/values (`test_contract_loaded_and_original_person2_devices_unchanged`).

## 2. Requirement (Person 2 canonical)

```json
{ "requirement_id": "req-…", "household_id": "hh_demo", "version": 1, "status": "DRAFT|CONFIRMED|DISABLED|RETIRED",
  "title": "…", "source_correction": "Don't turn off the hallway light while someone is there.",
  "scope": {"routine_ids": [], "devices": ["hallway_light"], "scenario_ids": ["sc-hallway-occupied"]},
  "preconditions": [{"op": "eq", "device": "hallway_occupancy", "attr": "occupied", "value": true}],
  "expected_behavior": {"kind": "must_not_set", "device": "hallway_light", "attr": "power", "value": "off"},
  "ambiguities": [], "confidence": 1.0, "interpreter": "p3c_deterministic_rules",
  "confirmation": {"by": "olivia", "at": "ISO-8601", "version": 1},
  "last_result": {"status": "FAIL", "run_id": "run-…", "candidate_id": "cand-…"} }
```

* Condition ops: `eq`, `neq`, `time_between{start,end}` (HH:MM, end exclusive; window may wrap midnight for must_not_set).
* Behavior kinds: `must_not_set` (no executed transition sets device.attr = value while preconditions hold) and
  `final_state_equals` (state at scenario end, or at the end of a `time_between` window).
* Lifecycle: created as DRAFT (never auto-confirmed) → `POST /requirements/{id}/confirm {version}` (owner) → CONFIRMED.
  Non-empty `ambiguities` block confirmation (`409 NEEDS_CLARIFICATION`). Any content edit creates version N+1 and returns
  the requirement to DRAFT until re-confirmed. DISABLED and RETIRED are kept (append-only versions) and listed in runs as
  `excluded`, never silently dropped. Confirm and edit require `version` / `expected_version` (`409 VERSION_CONFLICT`).

### Person 3C → Person 2 translation (`app/p3c_bridge.py`)

| Person 3C | Person 2 |
|---|---|
| `Condition{signal:"<room>_occupancy", op:"=="/"!=", value:bool}` | `{op:"eq"/"neq", device:"<room>_occupancy", attr:"occupied", value}` |
| `time_of_day >= a` and/or `<= b` | `{op:"time_between", start:a or "00:00", end:b or "00:00"}` |
| other signals (`mode`, `home_occupancy`, …) | **not translatable** → no draft; clarification question returned |
| `ExpectedBehavior.relation` `must_not_set` / `must_set` / `must_remain` | `kind` `must_not_set` / `final_state_equals` / `final_state_equals` |
| lock `lock: locked/unlocked`; security `armed: armed/disarmed` | `front_door.locked: true/false`; `security.armed: true/false` |
| `Scope{kind:"routine", id}` | `scope.routine_ids=[id]`, `scope.devices=[target]` |
| `Ambiguity[]` | `ambiguities: [question…]` (blocks confirmation) |
| `provenance.interpreter` | `interpreter: "p3c_<interpreter>"`, `confidence = heuristic_confidence` |

Scenario binding for new drafts: the non-edge household scenarios in which the state preconditions can hold
(`select_scenarios`); if none, the binding is left empty and the replay reports INCONCLUSIVE.

## 3. Routine and candidate

```json
{ "routine_id": "goodnight", "version": 2, "name": "Goodnight", "priority": 100, "enabled": true,
  "description": "Household edit: simplified Goodnight. The hallway occupancy condition was removed.",
  "triggers": [{"type": "event", "name": "goodnight"}], "conditions": [],
  "actions": [{"action_id": "a3", "device": "hallway_light", "attr": "power", "value": "off", "conditions": []}] }
```

Candidates wrap a routine version > baseline, status `PENDING_REVIEW|APPROVED|REJECTED`, `parent_candidate_id` for
repairs, `repair_ops`, `repair_source` (`deterministic_fallback|external_proposal`) and `repair_provenance`
(proposer, validator, evidence run/event ids, trace-grounded explanation, `ai_model_used`, `verified:false`).
Baselines and candidates are immutable (DB triggers). Approval never deploys (`deployed:false`).

### Repair ops (constrained)

Person 2: `add_action_condition{action_id,condition}`, `add_routine_condition{condition}`, `remove_action{action_id}`,
`add_action{action}`. Person 3C validator allowlist: `add_action_condition{index,condition}` (added for this
integration), `add_condition`, `remove_action{index}`, `modify_condition`, `change_action_value`. Translation
`p2_ops_to_p3c`; `add_action` is outside the P3C allowlist and is rejected when a P3C-sourced proposal is validated.

## 4. Replay, result semantics, trace

* `POST /replays {candidate_id, requirement_ids?, extra_scenario_ids?, via?}` → kind `full`, `targeted` or
  `exploratory` (edge-case scenarios; never used for approval; never updates `last_result`).
* Result: `PASS` (all evaluated assertions held, preconditions exercised), `FAIL` (an executed transition violated a
  requirement; evidence event ids given), `INCONCLUSIVE` (unknown state, unsupported operator, missing scenario,
  preconditions never exercised, incomplete trace). Suite: any FAIL → FAIL; else any INCONCLUSIVE or zero tests →
  INCONCLUSIVE; else PASS. Only `app/assertions.py` assigns these; the UI and AI copy them.
* Event ordering: queue key `(sim_minute, class_rank, seq)`; rank 0 scenario events (time, then declared order), 1 clock
  ticks, 2 state-change triggers; routines per event by `(priority, routine_id)`; actions in declared order; later
  writer wins; conflicts recorded. No wall clock, no randomness; `result_hash` = sha256 of trace + states.
* Run record pins `simulator_version`, `routine_versions`, `requirement_versions`, `requirement_statuses`,
  `scenario_versions`, `input_fingerprint`; `GET /replays/{id}/verify` re-simulates from the pinned inputs.
* Each run carries `integration {integration_mode:"simulated_demo", source_provenance:"local_fixture", invoked_via,
  correlation_id, adapter_version}` and `safety_statement`.

### Trace event (backend) and the spec's illustrative names

| Spec §13 name | Backend field |
|---|---|
| `event_id` | `event_id` (`E0001`…) |
| `sequence` | `seq` |
| `simulated_time` | `sim_time` (HH:MM) |
| `routine_id`, `routine_version` | same |
| `action` | `type` (`external_event|clock_tick|routine_fired|action`) + `kind`/`action_id` |
| `target_device_id` | `device` (+ `attr`) |
| `prior_state` / `resulting_state` | `previous` / `resulting` (plus full `state_before`) |
| `condition_evaluations` | `conditions[{scope, expr, actual, result(true|false|null)}]` |
| `source_event_id` | `source_event` (actions/routines) or `source` (scenario event id) |

Assertions reference events via `evidence_event_ids`. The frontend maps events to view kinds in
`src/api/canonicalMap.js` (`traceEventToView`) without changing ids or order.
